# Chill Run 仕様書

自分専用のランニング記録アプリ（Android）。
ふつうの記録に加えて、走りを日記のように残すことを目指す。残すものは次のとおり。

- 声のメモ（文字にする）
- 写真・動画
- 心拍数
- 高低差
- 10秒の「今日のランムービー」

## 前提

| 項目 | 内容 |
|---|---|
| 端末 | AQUOS R8 pro（Android 16）。**気圧センサーあり**（LPS22HH） |
| 走る場所 | 平地のロードと、生田緑地のトレイル（全体の高低差は 200m くらい。短い急坂の登り下りが多い） |
| イヤホン | Amazfit PowerBuds。心拍数を測れる。Zepp アプリで使っている |
| 体組成計 | AIfit アプリにつながっている。AIfit はヘルスコネクトに同期できる |
| 本人 | 1978年生まれ |
| 配布 | 自分用。Google Play には出さない |
| 作り | Kotlin と Jetpack Compose。ビルドは GitHub Actions、APK は Releases に置く |

**通信がない場所（山の中）でも、記録・お知らせ・声の文字化がすべて動く**ようにする。通信が必要なのは、地図の表示と、標高の補正だけ。

## 1. 走っている間

### 1-1. 記録
- スタート前に、次を選ぶ。
  - 種類：「ロード」か「トレイル」（9章）
  - メニュー：「自由に走る」「目標の距離」「目標の時間」「インターバル」
- GPS で、距離・時間・ペース・ルートを記録する。
  - 画面を消してポケットに入れても、止まらない。位置情報用の常駐サービス（foreground service、type `location`）を使う。
- 歩数センサー（`TYPE_STEP_DETECTOR` / `TYPE_STEP_COUNTER`）で、**ケイデンス**（1分あたりの歩数）を出す。
- 自動の一時停止：止まっている間（信号待ちなど）は、時間を止める（オン・オフ可）。
- 一時停止と終了は、間違えて押さないように**長押し**にする。

### 1-2. 高さ（標高）
- **気圧センサーを優先して使う。**
- 気圧は天気でも変わる。そこで、走り始めの地点の標高を、地図の標高データ（国土地理院の標高 API。通信がないときは GPS の高さ）で合わせる。そこからの上がり下がりを、気圧で測る。
- 獲得標高（登った高さの合計）は、細かいゆれを数えすぎないように、なめらかにしてから数える。例：2〜3m 以下の上下は無視する。
- 記録には、高さの測り方を残して、画面に小さく出す。「標高：気圧」または「標高：GPS」。

### 1-3. 声のお知らせ
- Android の読み上げ（TextToSpeech、日本語）で伝える。
- 読み上げている間だけ、音楽の音量を下げる（audio focus の `TRANSIENT_MAY_DUCK`）。
- **1km ごと**に、次を伝える。
  - 距離、この1km のペース、前の1km と比べて速いか遅いか
  - 心拍数とゾーン（心拍数が取れるとき。4章）
  - トレイルなら、この1km の登りと下り
  - アドバイスか励ましの言葉を1つ（下のルールで選ぶ）
- 例：「3キロ。ペース6分12秒、前より8秒速いです。心拍152、ゾーン3。いいリズム、このまま行こう」
- **励まし・アドバイスの選び方**（AI は使わず、ルールで選ぶ）
  - 場面ごとに、言葉の候補を10個以上用意する。同じ言葉が続かないようにする。
  - 場面の例：
    - ペースが上がった、落ちた、安定している
    - 後半に入った
    - 最後の1km
    - 登りの途中、下りの途中
    - 心拍数が高すぎる、余裕がある
    - 自己ベストのペース
  - 言葉は、ていねいすぎない話し言葉にする。例：「いいね」「そのまま」「無理しないで」
  - 言葉の候補は、アプリの中のファイル（JSON）にまとめる。あとで自分で書き換えられるように、設定から書き出し・読み込みできるようにする。
- **目標の手前のカウントダウン**（目標の距離・時間のとき）
  - 距離：「あと1キロ」「あと500メートル」「あと100メートル、ラストスパート！」
  - 時間：「あと5分」「あと1分」「あと10秒、9、8…」
  - 目標に届いたら、短い効果音と「目標達成！」
- お知らせの間隔（1km、500m、5分ごとなど）と、何を伝えるかは、設定で選べる。

### 1-4. インターバル
- 「走る ○分（または ○m）」「歩く・ゆっくり ○分」を、○回くり返す。
- 最初の「ウォームアップ」と最後の「クールダウン」も付けられる。
- 切り替えの3秒前から「3、2、1」と言い、切り替わったら振動させる。
- 作ったメニューは保存して、また使える。
- 記録には、走った区間ごとのペースを残す。

### 1-5. ロック画面に出す画面とボタン
- 走っている間は、スリープ中に電源ボタンを押すと、**ロックを解除しなくても**、このアプリの「走っている画面」が出るようにする（`setShowWhenLocked(true)`、`setTurnScreenOn(true)`）。
- 画面に出すもの：
  - 距離、タイム、ペース、心拍数（取れるとき）
  - 大きなボタンを3つ：**「メモ」「写真」「動画」**
  - ボタンは、汗や手袋でも押しやすい大きさにする（1つ 96dp 以上）。
- **通知の欄**にも、同じ3つのボタン（通知のアクション）を並べる。
- ロック画面から開いた画面では、ほかの画面（記録の一覧、設定など）には進めない。
- ボタンを押したときの動き：
  - **メモ**：ボタンを押すと録音を始め、もう一度押すと止める。最長60秒。始めと終わりに短い音と振動を出す。録音はロックしたままできる（常駐サービスの type に `microphone` を足す）。録音した地点と時刻を記録する。
  - **写真**：ロックしたままカメラの画面を開く（CameraX）。3秒のカウントダウンのあと、自動で撮る。画面のシャッターを押しても撮れる。撮った地点と時刻を記録する。
  - **動画**：写真と同じ流れで、3〜5秒の動画を撮る（長さは設定で選べる）。
- 撮った写真・動画・録音は、このアプリの中だけに保存する。スマホの写真フォルダには入れない（書き出したいときは、あとで共有メニューから）。

### 1-6. 音楽（ペースに合わせてテンポを調整）
- 音楽は、**このアプリの中で流す**。SpotifyなどほかのアプリではBPMを変えられないため。
- 曲は、スマホに入っている自分の曲（MP3・AAC・FLAC など）から選ぶ。フォルダか、プレイリストを指定する。
- **BPM を調べる**
  - 取り込んだ曲は、アプリが自動でテンポ（BPM）を調べて、結果を保存する。調べるのは初回だけ。
  - 調べた BPM が間違っていたら、手で直せる。曲に合わせて画面をタップして測る機能も付ける。
  - 倍・半分の BPM も、同じテンポとして扱う。例：85BPM の曲は、170歩/分に合う。
- **曲の選び方（2）**：次の曲は、いまの目標テンポに近い BPM の曲から選ぶ。
- **テンポの調整（1）**：選んだ曲を、**音程を変えずに速さだけ変えて**、目標テンポにぴったり合わせる。Media3 ExoPlayer の `PlaybackParameters` で、speed だけ変えて pitch は 1.0 のままにする。
  - 変える幅は、**±10% まで**（設定で ±5〜15%）。それ以上ずれる曲は選ばない。
  - テンポは、数秒かけてなめらかに変える。急に変えない。
- **目標テンポの決め方**（設定で選ぶ）
  - **いまの足に合わせる**：直近20〜30秒のケイデンスに合わせる。
  - **目標のペースに引っ張る**：目標のペースに合うケイデンスを目安にする。例：6分/km なら 168歩/分くらいから始めて、自分の記録で学習していく。ペースが目標より遅いときは、曲を2〜3% 速めにする。
  - **インターバル中**：「走る」と「歩く」で、目標テンポを切り替える。
- 曲の変わり目は、2〜3秒かけて重ねて切り替える（クロスフェード）。
- イヤホンのボタン（再生・停止、次の曲）で操作できる。

## 2. 走り終わったあと

### 2-1. 記録の画面
- **地図**
  - ルートを、**速さで色分け**して描く。遅いところは青、速いところはオレンジ。
  - 1km ごとの地点に、小さな数字を置く。
  - **声のメモ・写真・動画**を、残した地点に印で置く。タップすると、文字にしたメモ、写真、動画が開く。
- **数字**
  - 距離、タイム、平均ペース、最速の1km、ケイデンス、獲得標高と下りの合計、消費カロリー（目安）
- **グラフ**
  - ペース、標高、心拍数（取れたとき）を、横軸を距離にして並べる。
- **1km ごとの表**
  - ペース、心拍、登り・下り
- **声のメモの一覧**
  - 時刻と地点つき。文字はあとから直せる。
- **ひとことメモ**と、「今日の体調」の5段階（任意）
- **ロードかトレイルか**（9章）を、画面の上に大きく出す。例：「トレイル・獲得標高 +210m」

### 2-2. 地図
- 地図は、**国土地理院の地図（地理院タイル）**を使う。無料で、日本の地図がきれい。出典の表示が必要。山道も描かれている。
- 走る前に、よく走るあたりの地図を、端末に一時保存できるようにする。山の中で通信がなくても見られるようにするため。

### 2-3. 声のメモを文字にする
- **端末の中だけで**文字にする（山の中でも使えるように）。
  - 第一候補：Android の端末内の音声認識（`SpeechRecognizer.createOnDeviceSpeechRecognizer`、日本語）。
  - 録音したファイルからうまく文字にできない場合は、端末内で動くほかの音声認識（Vosk、whisper.cpp など）を提案してから使う。
- 走っている最中に文字にしなくてもよい。走り終わってから、まとめて文字にしてもよい。
- 文字にできなかったメモは、録音のまま残して、再生できるようにする。

### 2-4. 10秒の「今日のランムービー」
- 走り終わったら、ボタン1つで作る。設定で「自動で作る」も選べる。
- 長さはおよそ10秒。縦長（9:16）。
- 中身の流れ（例）：

| 時間 | 内容 |
|---|---|
| 0〜1.5秒 | 「ROAD」または「TRAIL」、日付、場所の名前（例：生田緑地） |
| 1.5〜5秒 | 地図の上にルートが描かれていくアニメーション。トレイルのときは、標高のグラフも一緒に伸びていく |
| 5〜8.5秒 | 撮った写真・動画を、短く切り替えて見せる（最大4つ）。声のメモから1つ、字幕のように出す |
| 8.5〜10秒 | 距離・タイム・平均ペース・獲得標高。月のまとめ（例：「今月 42km」）を小さく |

- 写真・動画がない日は、地図と数字だけで作る。
- 音：アプリに入っている、権利の心配のない短い音楽か、音なし。自分の曲は使わない（SNS に載せたときに困らないように）。
- 作り方：Media3 Transformer などで、端末の中で作る。地図のアニメーションは、アプリで1コマずつ描いて動画にする。
- できた動画は、アプリの中に保存する。共有メニューから、写真フォルダや SNS に書き出せる。

### 2-5. 自宅のまわりを隠す
- 設定で「隠す場所」（自宅など）を決められる。
- 地図の書き出しとランムービーでは、その場所から半径200m（設定で変えられる）のルートを描かない。
- アプリの中の記録の画面では、全部見られる。

## 3. ヘルスコネクト

データの受け渡しは、Android の**ヘルスコネクト**でまとめて行う。

| 向き | データ | 使い道 |
|---|---|---|
| 書き込む | ランの記録（`ExerciseSessionRecord` の RUNNING。トレイルは RUNNING のまま、タイトルに「トレイル」と入れる）、ルート（`ExerciseRoute`）、距離、獲得標高、ケイデンス、消費カロリー | Google Fit など、ヘルスコネクトに対応したアプリから見られる |
| 読み込む | 心拍数（`HeartRateRecord`。Zepp から） | 走り終わったあと、ランの時間帯の心拍数を取り込む（4章） |
| 読み込む | 体重（`WeightRecord`）、体脂肪率（`BodyFatRecord`）、ほか入っていれば筋肉量など（AIfit から） | ふりかえり（8章） |
| 読み込む | 安静時の心拍数（`RestingHeartRateRecord`） | 心拍ゾーンの計算（4章） |

- **同じランが2回記録されないようにする。**
  - Zepp も運動の記録をヘルスコネクトや Google Fit に書き出すので、同じランが2つ入ることがある。
  - 取り込むときは、ランと同じ時間帯の心拍数だけを使う。
  - 説明書には、「Zepp からは運動の記録を書き出さず、心拍数だけ書き出す」ための設定の手順を書く。Zepp の設定で、どこまで選べるかは実機で確かめる。
- **段階1の最初に、実機で確かめる。**
  - Zepp（PowerBuds）の心拍数が、ヘルスコネクトに入るか。入るなら、どれくらい細かい間隔か。
  - AIfit の体重・体脂肪率が入るか。それ以外の項目も入るか。

## 4. 心拍数

### 4-1. 取り方（2通り）
1. **走っている最中にリアルタイムで受け取る**（できれば）
   - PowerBuds が、Bluetooth の標準の心拍数の形式（Heart Rate Service `0x180D`）で数値を流していれば、直接つないで受け取る。
   - 確かめ方：無料アプリ「nRF Connect」で PowerBuds を探し、「Heart Rate」の項目があるかを見る。この手順を説明書に書く。
   - ほかの方法でリアルタイムに受け取れる場合（Zepp が心拍数を外に流す機能があるなど）も、見つかれば使う。
2. **走り終わってから取り込む**（1ができないとき）
   - ヘルスコネクトから、ランの時間帯の心拍数を読み込んで、記録に付ける（3章）。
   - この場合、走っている最中の心拍数のお知らせはできない。
- どちらで取れたかを、記録に残す。

### 4-2. 心拍ゾーン
- **カルボーネン法**で5つのゾーンに分ける。
  - 計算式：（最大心拍数 − 安静時心拍数）× 強さ ＋ 安静時心拍数
- 最大心拍数
  - 最初は、年齢からの目安を使う（208 − 0.7 × 年齢）。
  - 自分で測った値があれば、それを優先する。
  - 走った記録の中で、これまでの最大より高い値が出たら、「最大心拍数を更新しますか？」と聞く。
- 安静時心拍数：ヘルスコネクトにあれば、それを使う。なければ手で入れる。
- ゾーンの名前：1 とても楽、2 楽（ゆっくりジョグ）、3 ややきつい、4 きつい、5 とてもきつい

### 4-3. 心拍数のお知らせ（リアルタイムで取れるとき）
- 1km ごとのお知らせに、心拍数とゾーンを入れる。
- **ペースが今日に合っているか**を、心拍数から判断して伝える。
  - メニューごとに、目標のゾーンを決めておく。例：「ゆっくりジョグ」はゾーン2、「ペース走」はゾーン3〜4。インターバルの「走る」はゾーン4。
  - 目標のゾーンより高い状態が60秒続いたら：「心拍が上がりすぎ。少しペースを落とそう」
  - 目標のゾーンより低い状態が2分続いて、本人が速く走りたいメニューのとき：「まだ余裕あり。少し上げてもいいよ」
  - 登りで心拍数が上がるのは当たり前なので、トレイルの登りでは注意をゆるめる。
- 注意は、同じ内容を何度も続けて言わない。一度言ったら、次は2分以上あける。

### 4-4. 安全のための表示
- 心拍ゾーンは、トレーニングの目安で、体調や病気の判断に使うものではないことを、設定画面と説明書に書く。
- 「胸の痛み、強い息切れ、めまい、ふらつきがあれば、数字に関係なくすぐに止まって休む」ことも書く。
- 最大心拍数の年齢からの目安は、人によって大きくずれることがあると書く。

## 5. 記録の画面に出す「一目で分かる」印

- **ロード**は海の青、**トレイル**は森の緑の印を付ける。
  - 記録の一覧の各行
  - 記録の画面の上
  - ランムービーの最初
- 記録の一覧の各行には、**標高の小さなグラフ**（山の形）を出す。平らか山あり谷ありかが、パッと分かるようにする。

## 6. 設定

- プロフィール
  - 生まれた年（初期値 1978）
  - 体重（ヘルスコネクトから取れればそれを使う）
  - 安静時・最大心拍数
- お知らせ
  - 間隔、伝える項目、声の速さ、音量
  - 励ましの言葉の書き出し・読み込み
- 心拍ゾーンと、メニューごとの目標ゾーン
- 音楽
  - 曲のフォルダ
  - BPM の一覧と手での修正
  - 変える幅
  - 目標テンポの決め方
- 地図
  - 地図の一時保存
  - 隠す場所
- トレイルの判定の目安（9章）
- ランムービーを自動で作るかどうか
- ヘルスコネクトの許可の状態
- 書き出し・読み込み（全データのバックアップ）

## 7. 許可

- 位置情報
  - 正確な位置
  - 「アプリの使用中のみ」で足りるように作る。常駐サービスを、画面を開いている間に始めるため。
- 常駐サービス：location、microphone、camera
- 通知
- 身体活動（歩数センサー）
- マイク、カメラ
- Bluetooth の接続とスキャン（心拍数を直接受け取る場合）
- ヘルスコネクトの読み書き
  - 運動、ルート、距離、標高、心拍数、体重、体脂肪率、安静時心拍数
- 曲のファイルの読み込み
- 電池の最適化の対象外：走っている最中に止められないように。初回に案内する。

「許可の状態」の画面を作る。足りない許可は、ボタン1つでその設定画面に飛べるようにする。

## 8. ふりかえり（やる気を上げる）

- **カレンダー**：走った日に印を付ける。ロードは青、トレイルは緑。
- **週・月のまとめ**
  - 距離（ロードとトレイルで色分け）
  - 回数
  - 獲得標高の合計
  - 走った時間
- **自己ベスト**
  - 1km・5km・10km の最速
  - 一番長い距離
  - 一番登った日
  - **コースごと**のベスト（9章のいつものコース）
- **体の変化**
  - 体重・体脂肪率（ヘルスコネクトから）を、**7日間の平均**の線で出す。毎日の上下で一喜一憂しないようにする。
  - 走った距離と、同じグラフに重ねて見られる。
  - 月のまとめに「今月は 42km 走って、体脂肪率は −0.8%」のように出す。
- **同じペースでの心拍数の変化**
  - 例：「6分30秒/km で走ったときの平均心拍が、先月より4下がった」
  - 体力がついたことを、数字で伝える。
- 励ましは、数字よりも**続けたこと**をほめる。例：「今月は8回走った」
  - 体重が増えた週も、責める言い方はしない。

---

## 9. ロードかトレイルかの判定

- 基本は、スタート前に本人が選ぶ。
- 走り終わったあと、次の目安で自動で判定して、選んだものと違えば「トレイルに変えますか？」と聞く（その場で変えられる）。
  - 1km あたりの登りが **15m 以上**
  - 坂（勾配 10% 以上）を通った距離が、全体の **10% 以上**
  - 地図の情報で、未舗装の道・登山道・遊歩道を通った割合（OpenStreetMap の道の種類などが使えれば）
  - 上のうち2つに当てはまれば、トレイルの候補にする。目安の数字は設定で変えられる。
- **いつものコースを覚える**
  - ルートの形が似ているランを、同じコースとしてまとめる。例：スタートとゴールが近く、ルートの 70% 以上が重なる。
  - コースには名前を付けられる。例：「生田緑地」
  - 一度トレイルと決めたコースは、次からも自動でトレイルにする。
  - コースごとの自己ベストと、回数を出す。

## 10. 見た目

- シンプルで見やすくする。走りながら一瞬で読めることを最優先にする。
- 走っている画面
  - 数字は大きく、細すぎない字にする。
  - 屋外の日差しの下でも読めるよう、背景は暗く、数字は明るくする。
- ロードの青（海）、トレイルの緑（森）を、アプリ全体の色の軸にする。
- 細かいデザインは、段階1ができてから相談して決める。
