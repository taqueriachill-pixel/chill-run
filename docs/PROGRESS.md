## 実機で分かったこと（2026-11-12）

- 気圧センサー（lps22hh）、歩数センサー（1歩ごと・合計）あり。日本語の読み上げは通信なしで使える声が5個。
- ヘルスコネクトの許可は 16/16。心拍数・体重などは「データなし」（Zepp と AIfit をまだヘルスコネクトにつないでいない）。
  運動の記録は Google Fit が自動で書いたウォーキング（種類番号79）が128件。
- Zepp の PowerBuds の「運動設定」に **「アクティビティ心拍数の共有」**（付近のスマートデバイスが心拍数データを取得できる）があり、オンになっている。
  → 心拍数を Bluetooth で直接流している見込みが高い。標準の形式（0x180D）かどうかを nRF Connect で確かめる（`docs/SETUP.md` の 8）。
  流れるのがワークアウト中だけかどうかも、あわせて確かめる。

- nRF Connect では PowerBuds につながらなかった（ペアリング済みの番号で DISCONNECTED のまま、CLIENT が空）。
  英語の点検アプリは本人には扱いにくいので、同じ確認を Chill Run の「実機チェック」に組み込んだ
  （「心拍数の機器をさがす」：まわりをスキャン → 0x180D を名乗る機器や PowerBuds らしい機器につなぐ → 数字が届くか15秒待つ）。
  このために Bluetooth の許可（付近のデバイス）を追加した。段階4の受信部分の下地にもなる。

- 本人はスマートウォッチ **Zeblaze Btalk 2 Lite**（手首で心拍数を測る）も持っている。nRF Connect でつながり、
  **Heart Rate（0x180D）の項目がある**ことを確認（写真）。数字が実際に流れるかは未確認。
  流れれば、PowerBuds の代わりにこの時計から走っている最中の心拍数を受け取れる。
  実機チェックの「心拍数の機器をさがす」は、ペアリング済みの機器も名前に関係なく試すように広げた。

- **確定：Btalk 2 Lite から心拍数を直接受け取れる。** nRF Connect で Heart Rate Measurement（0x2A37、NOTIFY）に
  「89 bpm, Contact is Detected」が届いた（写真）。ただし**時計側でランニングのモードを始めたときだけ**流れる。
  → 段階4は「走っている最中にリアルタイムで受け取る」方式で作れる。走る前に時計のランニングモードを始める手順が要る。
  時計の番号は 99:CB:B9:28:9E:54（ペアリング済み）。PowerBuds 側は未確認のまま（必要なら実機チェックで調べる）。

## 段階1で決めたこと

### 全体
- アプリの ID：`com.chill.run`。対応は Android 14 以上（minSdk 34）、Android 16 向け（targetSdk 36）。
- Kotlin + Jetpack Compose。画面の切り替えは自前の簡単な仕組み（`MainActivity` の `route`）。
- ビルド：GitHub Actions（`.github/workflows/build.yml`）。どのブランチに push しても動く。
  - 鍵が登録済み → 固定の鍵で署名した APK を作り、Releases に `v0.1.<実行番号>` として置く。
  - 鍵が未登録 → 仮の鍵でビルドが通るかだけ確かめる（配らない）。
- 署名の鍵：Claude が作成し、本人にチャットで渡した。別名（alias）は `chillrun`。リポジトリには入れない。
- Claude の作業場所では Android のビルドができない。計算部分（`core`）だけは手元でテストできる
  （Gradle に入っている Kotlin コンパイラを使用）。それ以外は GitHub Actions の結果で確認する。
- Claude からは GitHub の Secrets を読み書きできない。

### 記録
- 位置は Android 標準の GPS（`LocationManager` の GPS_PROVIDER、1秒ごと）。Google Play 開発者サービスには頼らない。
- 精度 30m より悪い位置は使わない。2.5m 未満の動きは足さない（止まっているときのゆれ対策）。秒速12m を超える飛びは捨てる。
- 常駐サービスは type `location` のみ（`microphone` と `camera` は段階3で足す）。走っている間は CPU を起こしたままにする（wake lock）。
- 自動の一時停止：歩数が4秒なく、速さが秒速0.8m 未満なら止める。3秒で3歩以上、または秒速1.5m 超で再開。
  歩数センサーが使えないときは速さだけで判定。急坂をゆっくり歩いても止まらない。
- ケイデンス：歩数センサー（1歩ごと）の直近20秒から計算。
- 途中でアプリが落ちた場合：次に開いたときに、保存済みの地点から記録を仕上げる。
- 20m 未満で終了した記録は保存しない。

### 標高
- 気圧センサーを優先。気圧から出した高さ（相対値）を地点に保存し、ランごとの「ずれ」（`altOffset`）を足して標高にする。
- 開始地点の標高：最初の良い位置（精度20m 以内）で、まず GPS の高さで仮に合わせ、国土地理院の標高 API が取れたら置き換える。
- 獲得標高：なめらかにしてから、2.5m 以上の向きの変化だけ数える（気圧がない端末は 6m）。
- 記録に「標高：気圧／GPS」と「開始地点の合わせ方：地理院／GPS」を残す。

### 声のお知らせ
- 間隔：500m・1km・2km・5分・10分から選ぶ（初期は 1km）。伝える項目（ペース・前との比較・励まし）もオン・オフできる。
- 励ましの言葉：12 の場面 × 10 個を `assets/phrases.json` に用意。設定から書き出し・読み込み・初期に戻すができる。
  段階1で使う場面は 走り始め／ペースが上がった・落ちた・安定／後半に入った／最後の区間／目標達成。
  登り・下り・心拍・自己ベストの言葉は用意だけしてあり、段階2・4・6で使う。
- 目標の手前：距離は あと1km・500m・100m、時間は あと5分・1分・10秒から1秒ごと。達成で効果音＋振動＋「目標達成！」。
- 通信なしで使える日本語の声があれば、それを優先して使う。

### 画面
- ホーム（種類・メニュー・スタート）、走っている画面（ロック中も表示、長押しで一時停止・終了）、
  記録の一覧、記録の画面（数字・1km ごとの表・ルートの形・標高の線）、設定、許可の状態、実機チェック。
- 色：ロード＝海の青 `#2E9BD6`、トレイル＝森の緑 `#3DAA6B`。走っている画面は黒地に白の大きな数字。
- 細かいデザインは、段階1の実機確認のあとで相談する（仕様10章）。

### ヘルスコネクト
- 書き込み：運動（RUNNING。トレイルは題に「トレイル」）、ルート、距離、獲得標高、ケイデンス、消費カロリー。
  ランごとに決まった番号を付けるので、書き直しても二重にならない。
- 読み込み（段階1では実機チェックと体重の取り込みだけ）：心拍数、安静時心拍数、体重、体脂肪率、除脂肪体重、骨量、体水分量、基礎代謝、運動の記録。
- 消費カロリーの目安：体重 × 距離(km) × 1.036 ＋ 登りの分。

## 段階2で決めたこと

### 地図
- 地図の部品は自前で作った（外部のライブラリは使っていない）。国土地理院の「標準地図」のタイルを表示する。
  画面の細かさに合わせてタイルを大きめに描き、文字が小さくなりすぎないようにしている。
- 一度見たタイルは端末の中（アプリ専用の場所 `files/tiles/std`）に取っておく。消すのは「地図の一時保存」の画面から。
- 地図の左下に「出典：国土地理院（地理院タイル）」を常に出す。
- ルートの色分け：そのランの中で、遅いほう1割〜速いほう1割のあいだを 青 `#2E6FE6` → オレンジ `#FF8A1F` で塗る。
- 1km ごとに白丸の数字。スタートは緑の丸、ゴールは赤の丸。
- 地図の一時保存：地図の真ん中から半径 2・3・5km、ズーム 12〜17 を保存。4枚ずつ取ってくる。
  （ズーム18 は枚数が4倍になるので入れていない。見たときに自動で取っておかれる分で足りる想定）

### 標高・グラフ
- 記録の画面：標高（山の形に塗る）とペースのグラフ。横軸は距離、縦線は 1km ごと。心拍数のグラフは段階4で足す。
- 記録の一覧：各行の右に標高の小さなグラフ。高低差 30m 未満はほぼ平らに見えるようにしている。
- トレイルのお知らせ：区切りごとに「登り○メートル、下り○メートル」（3m 以上のとき）。
  登りが下りより 15m 以上多い区間は「登りの途中」、逆は「下りの途中」の言葉を使う。

### ロードかトレイルかの判定
- 走り終わったあと、①1km あたりの登りが目安（初期 15m）以上、②勾配10%以上の坂を通った割合が目安（初期 10%）以上、
  の**両方**に当てはまればトレイルの候補。選んだ種類と違えば、記録の画面で「トレイルに変えますか？」と聞く
  （逆に、トレイルを選んだのに当てはまらないときは「ロードに変えますか？」）。目安は設定で変えられる。
- 仕様の3つ目の目安（OpenStreetMap で未舗装かどうか）は**まだ入れていない**。通信が必要で、取れないことも多いため。
  必要なら後で「通信があるときだけの、おまけの材料」として足す。
- 坂の割合は、30m 進むごとの高さの変化から出している。

### いつものコース
- ランごとに、ルートを 50m ごとの点にした「形」を保存。スタートとゴールがそれぞれ 200m 以内で、
  互いのルートの 70% 以上が 60m 以内を通っていれば同じコース。逆回りは別のコースになる。
- 2回目に似たルートを走ったとき、自動で「コース1」などの名前でまとまる。記録の画面で名前を付けられる。
- 種類を変えたり「このまま」と答えたりすると、そのコースの種類として覚え、次からは自動でその種類にする（もう聞かない）。
- 記録の画面に、そのコースで何回目か・コースのベスト（平均ペース）を出す。

### インターバル

## 段階3で決めたこと

### 走っている画面と通知
- 走っている画面に「メモ」「写真」「動画」の大きなボタン（高さ 100dp、1回押すだけ）を追加。一時停止・終了は長押しのまま。
  場所を空けるため、距離の数字を少し小さくした（104sp → 88sp）。
- 通知にも同じ3つのボタン。メモは常駐サービスに直接届き、写真・動画は撮影の画面を開く。
  **ロック中に通知のボタンから撮影の画面を開けるかは、実機で未確認。**

### 声のメモ
- 押すと録音開始、もう一度押すと停止、最長60秒。始めと終わりに短い音と振動。録音した時刻・地点・距離を記録。
- 録音は WAV（16kHz・モノラル・加工なし）。60秒で 2MB 弱。文字にしやすい形を優先した。
- 始まりの合図の音が録音に入らないよう、合図から 0.45秒待って録り始める。録音中は声のお知らせを止める。
- 常駐サービスの type は `location|microphone`。**マイクの許可があるときだけ** microphone を付けて始める
  （許可がないのに付けると、サービスを始められないため）。だから、マイクの許可は走り出す前に必要。
- 0.5秒より短い録音は残さない。

### 写真・動画
- CameraX を使った専用の画面（`CaptureActivity`、ロック中も表示）。3秒のカウントダウンのあと自動で撮る。「すぐ撮る」も可。
- 動画は 3〜5秒（設定で選ぶ、初期 4秒）、画質は HD。マイクの許可があれば音も入る。
- カメラは画面が出ているときだけ使うので、常駐サービスの type に `camera` は足していない（仕様 7章からの変更。足さなくても動くため）。
- 写真・動画・録音は、アプリ専用の場所（`files/media/<ランの番号>/`）だけに保存。写真フォルダには入らない。
  書き出したいときは、大きく見る画面の「共有」から（FileProvider）。

### 文字にする
- 仕様の第一候補どおり、端末内の音声認識（`SpeechRecognizer.createOnDeviceSpeechRecognizer`、ja-JP）に、
  録音ファイルの音を流し込む。まず「長い録音を最後まで聞く」やり方で試し、だめなら「ひと息ぶんだけ」でもう一度試す。
- 走っている最中は文字にしない。記録の画面を開いたときに、まだ文字にしていないメモを1つずつ文字にする。
- 文字にできなかったメモは録音のまま残し、再生できる。文字はあとから直せる。「もう一度」でやり直せる。
- **AQUOS R8 pro で実際に文字にできるかは未確認。** 実機チェックに「5秒話して試す」を入れたので、その結果で決める。
  だめなら Vosk か whisper.cpp を提案する（仕様 2-3）。

### 記録の画面
- 地図の上に、残した地点の印（声＝黄土色、写＝紫、動＝赤）。押すと開く。
- 「声のメモ」の一覧（時刻・地点・文字・再生・直す・もう一度・消す）と、「写真・動画」の見本の一覧。
- ランを消すと、そのランのメモ・写真・動画も消える。

### データベース
- 版を 2 → 3 に上げ、media 表を足した。引っ越しあり。`MigrationTest` は「いまの版で足した表」を突き合わせる形に直した。

## 段階4で決めたこと

### 取り方
- **走っている最中にリアルタイムで受け取る**（仕様 4-1 の 1）を主にした。設定で選んだ機器（Btalk 2 Lite を想定）に
  Bluetooth でつなぎ、標準の心拍数の通知（0x180D / 0x2A37）を受け取る。切れたら自動でつなぎ直す。
  機器が「肌から外れている」と知らせてきたときの数字は使わない。
- 機器の選び方：設定 →「心拍数の機器を選ぶ・試す」。ペアリング済みの機器と、まわりで心拍数を流している機器を一覧に出す。
  その場でつないで、数字が出るかを試せる。
- **走り終わってから取り込む**（仕様 4-1 の 2）も残した。リアルタイムで1つも取れなかったランは、終了時に
  ヘルスコネクトをさがし、あれば取り込む。記録の画面からも手で取り込める。
- どちらで取れたかを記録に残す（「心拍数：リアルタイム／ヘルスコネクト」）。
- 機器を選んであるのに 90秒たっても届かないときは、一度だけ声で知らせる。

### 心拍ゾーン
- カルボーネン法。ゾーン1＝強さ 50〜60%、…、ゾーン5＝90% 以上。50% 未満は「ゾーン外」。
- 最大心拍数：初期は年齢からの目安（208 − 0.7 × 年齢）。設定で自分の値に変えられる。
  ランの中で、5地点続けて設定より高い値が出たら、記録の画面で「最大心拍数を更新しますか？」と聞く
  （一瞬だけの高い値では聞かない。「しない」と答えた値以下では、もう聞かない）。
- 安静時心拍数：初期 60。設定で手で入れるか、ヘルスコネクトの値を入れる。
- 過去の記録のゾーンごとの時間は、**いまの設定**で計算し直して出す。

### お知らせ
- 区切りごとのお知らせに「心拍152、ゾーン3」を入れる（設定で切れる）。
- ホームに「今日のねらい」（なし／ゆっくりジョグ／ペース走）を追加。心拍数の機器を選んであるときだけ出る。
  - ゆっくりジョグ：目標ゾーン 2。上がりすぎだけ知らせる（「上げてもいいよ」とは言わない）。
  - ペース走：目標ゾーン 3〜4。上がりすぎと、余裕がありすぎの両方を知らせる。
  - インターバル：「走る」の間だけ、目標ゾーン 4 で見張る。「ゆっくり」の間は見張らない。
  - 目標ゾーンは設定で変えられる。
- 目標より高いゾーンが 60秒 続いたら「落とそう」、低いゾーンが 2分 続いたら「上げてもいいよ」。同じ注意は 2分以上あける。
- トレイルの登りの途中（直近30秒で 3m 以上登った）は、1ゾーン上までは注意しない。

### 安全のための表示（仕様 4-4）
- 設定の「心拍数」の欄、記録の画面のゾーンの欄、`docs/SETUP.md` の 11-4 に書いた。

### データベース
- 版を 3 → 4 に上げ、runs に平均・最大の心拍数、取り方、今日のねらいを、points に心拍数を、splits に平均の心拍数を足した。引っ越しあり。

### 仕様から変えた点・入れていないもの
- ヘルスコネクトへは、心拍数を書き込んでいない（仕様3章の「書き込む」の表に心拍数がないため）。
- ヘルスコネクトの安静時心拍数は、自動では使わず、設定のボタンで入れる形にした（勝手に変わると、ゾーンが日によってずれるため）。

## 段階5で決めたこと

### 曲の取り込み
- 曲のフォルダは、Android のフォルダ選び（ストレージ アクセス フレームワーク）で選ぶ。写真や音楽全体への許可は求めない。
  下のフォルダも読む。読める形式は mp3・m4a・aac・flac・ogg・opus・wav。
- **プレイリスト（m3u など）の指定は入れていない。** フォルダの指定だけ。必要なら後で足す。
- 曲の一覧は tracks 表に保存（場所・題名・アーティスト・長さ・BPM・手で直したか・使うか）。

### BPM の自動判定
- 自前で作った。曲の 1/5（最大30秒）進んだ所から 60秒ぶんを取り出し、音の立ち上がりの強さの並びから、
  いちばんよく繰り返すテンポ（60〜200BPM）を選ぶ。120BPM 付近を少しだけ優先する。
- 調べるのは初回だけで、結果を保存する。にせもののクリック音（85〜174BPM）では、倍・半分を含めて当たることをテストで確認。
  **本物の曲でどれくらい当たるかは、実機で未確認。** 外れたら手で直せる（±1、倍、半分、タップで測る、自動で調べ直す）。
- 手で直した BPM は、自動では書き換えない。

### 曲選びとテンポの調整
- 倍・半分の BPM は同じテンポとして扱う（85BPM の曲は 170歩/分に合う）。
- 目標テンポに対して、速さを変える幅（初期 ±10%、設定で ±5〜15%）に収まる曲の中から選ぶ。最近かけた曲は避ける。
  収まる曲がないときは、いちばん近い曲を幅の端の速さで流し、画面にその旨を出す（仕様は「選ばない」だが、無音よりよいと判断）。
- 速さは Media3 ExoPlayer の `PlaybackParameters(speed, pitch = 1.0)` で変える。1秒に 1% ずつ。
  目標テンポはならしながら追いかけ、0.8% より小さいずれは放っておく（細かく変え続けると聞きづらいため）。
- 曲の変わり目は、プレイヤーを2つ使って 2.5秒かけて重ねる。

### 目標テンポ
- **いまの足に合わせる**（初期）：直近20秒のケイデンス。止まっている間は、いまのテンポのまま。
- **目標のペースに引っ張る**：目標のペース（初期 6:00/km）に合うケイデンス。5秒/km 以上遅れていたら 2.5% 速めにする。
- ペース → ケイデンスの見積もり：初めは「6:00/km で 168歩/分、30秒速くなるごとに 3歩増える」。
  1km の記録が 8個以上たまると、自分の記録（ペースとケイデンス）から学ぶ。
- **インターバル中**：区間が切り替わったら、すぐ曲を切り替える。「走る」以外の区間は、設定した歩くテンポ（初期 120）
  または、いまの足（「いまの足に合わせる」のとき）。

### 音の扱い
- 声のお知らせの間は、アプリ自身で音楽の音量を 25% に下げる（読み上げの始めと終わりの合図を受けて切り替える）。
- 声のメモの録音中も、音楽を小さくする。
- 電話などで音の優先権を失ったら止め、戻ったら再開する。
- イヤホンのボタン：Android 標準の MediaSession で、再生・停止・次の曲を受ける。
- 常駐サービスの type に `mediaPlayback` を足した（音楽を流す設定のときだけ付ける）。

### データベース
- 版を 4 → 5 に上げ、tracks 表を足した。引っ越しあり。

## 段階6で決めたこと

### ランムービー
- 720×1280（縦長 9:16）、30コマ/秒、10秒、H.264、**音なし**（仕様の「権利の心配のない短い音楽か、音なし」のうち、音なしを選んだ）。
- 作り方は自前：1コマずつ Android の Canvas で絵を描き、色を動画用（YUV）に直して、MediaCodec で固め、MediaMuxer で mp4 にする。
  Media3 Transformer は使っていない（実機で試せない中では、部品が少ないほうが確実と判断）。
- 流れ：0〜1.5秒 題（ROAD／TRAIL、日付、コースの名前）→ 1.5〜5秒 地図にルートが描かれる（トレイルは標高のグラフも）→
  5〜8.5秒 写真・動画（最大4つ。多いときは全体からまんべんなく）と、声のメモの字幕（最初の1つ）→ 8.5〜10秒 数字と「今月 ○km」。
  写真・動画がない日は、地図を 8.5秒まで続ける。
- 場所の名前は、いつものコースの名前を使う（コースに入っていないランでは出さない）。
- 動画は、最大6コマ（0.15秒おき）を取り出して見せる（メモリを使いすぎないため。なめらかな再生ではない）。
- 地図には「出典：国土地理院（地理院タイル）」を入れる。
- できたムービーは media 表に種類 `MOVIE` として保存（ランごとに1つ。作り直すと置きかわる）。記録の画面から見る・共有する。
- 設定で「走り終わったら自動で作る」を選べる（初期はオフ）。

### 隠す場所
- 1か所だけ決められる（地図の真ん中を指定、半径 100〜1000m、初期 200m）。
- ランムービーでは、その中のルートを描かない。地図の表示範囲も、隠した部分を除いたルートに合わせる。
- **「地図の書き出し」の機能そのものがまだないので、効くのはランムービーだけ。** アプリの中の地図は全部見える（仕様どおり）。

### ふりかえり
- ホームに「ふりかえり」を追加。カレンダー（ロード＝青、トレイル＝緑）、月・週のまとめ、自己ベスト、コースごとのベスト、
  同じペースでの心拍数の変化、体の変化。
- 自己ベストの 1km・5km・10km は、ランの中の「いちばん速かった区間」（区切りの位置に関係なく探す）。ランごとに保存しておく。
- 同じペースでの心拍数：1km ごとの記録を 30秒きざみのペースの組（6:30/km なら 6:15〜6:45）に分け、今月と先月の両方に 2つ以上ある組のうち、
  いちばん数の多い組で比べる。差が 2 未満なら「ほぼ同じ」。上がっていても、責める言い方はしない。
- 体の変化：ヘルスコネクトの体重・体脂肪率を、直近120日ぶん、7日間の平均の線で出す。うしろに週ごとの距離の棒を重ねる。
  縦の幅は最低 2（kg／%）取って、少しの変化が大げさに見えないようにしている。
- 励ましは、回数（続けたこと）をほめる。体重や体脂肪率が増えても責めない。

### ひとことメモと体調
- 記録の画面に、今日の体調（つらい／重い／ふつう／良い／絶好調）と、ひとことメモ（500字まで）を追加（仕様 2-1）。

### バックアップ
- 1つの zip に、全部の表の中身（JSON）、設定、励ましの言葉、（選べば）声のメモ・写真・動画をまとめる。
- 読み込みは「全部置きかえ」。新しい版のバックアップは読み込まない。読み込んだあとは、アプリを閉じて開き直してもらう。
- 音楽の曲と、地図の一時保存は入れない。
- 表を足したら `Backup.TABLES` と `Backup.DB_VERSION` も直す（直し忘れはテストで分かる）。

### データベース
- 版を 5 → 6 に上げ、runs に 1km・5km・10km の最速、ひとことメモ、体調を足した。引っ越しあり。

## ランムービーの曲（本人の希望で追加。2026-11-13）

- 本人の希望：ランムービーに、ランダムに作った音楽を入れたい。トレイルかロードか、つらかったか楽しかったか、
  寒かったか暑かったか、晴れか雨か、などを**組み合わせて**決めてほしい。
- 作り方：既存の曲や AI は使わず、決まりごとで作曲して音を合成する（`core/RunTune.kt`。Android に頼らないのでテストできる）。
  10秒・**2チャンネル（ステレオ）**・44.1kHz を作り、AAC（192kbps）にして動画に入れる。作るのにかかるのは PC で 1秒以下。
- **2版目（2026-11-13 夕方）**：1版目の曲を本人が聞いて「センスを上げてほしい。ジャジー、Lo-fi、ハウス、クラブっぽい法則を調べて、それに沿って」。
  調べたお決まりに沿って、4つの型に作り直した：
  - ローファイ：70〜86BPM、16分のはね 58〜62%、キックは1拍目と「3拍目の少し前」、スネアは2・4拍で少し後ろ、ハイハットの強さをばらつかせる、
    7th・9th のエレピ和音を指をずらして弾く、レコードのぱちぱち音、回転むら、3.8kHz より上を落とす、軽いサイドチェイン。
  - ジャジー：96〜114BPM、8分のはね 64%、ライドは4分＋2・4拍の裏、ハイハットは2・4拍、キックはごく小さく（フェザリング）、
    歩くベース（拍の頭は根音、次は次の根音へ半音で近づく）、エレピの合いの手はチャールストンのリズム（裏の一打は次の和音を先取り）、ビブラフォンの旋律。
    和音は ii–V–I–VI（最後の V はときどき半音上の代理和音）。
  - ディープハウス：120〜126BPM、4つ打ち、クラップ2・4拍、裏拍のオープンハイハット、16分のハイハットは小さく、シェイカー、
    m9・maj9 の短い和音をシンコペーションで、裏拍のベース、強いサイドチェイン（キックで音がうねる）、1小節目はこもらせて開いていく、
    盛り上げのノイズ、最後の2拍はドラムを抜いてスネアの連打で「ため」。
  - クラブ：122〜128BPM、短調、16分の分散和音（3-3-2 の強弱）、パッド、ハウスと同じドラムとうねり、やまびこ付きの旋律。
  - 共通：和音は全部 7th 以上（M7・M9・6/9・m7・m9・7・9・13・m7b5）。前の和音から近い音へつなぐ（根音はベースに任せて抜く）。
    旋律は1小節の「ひとふし」を作ってくり返し、拍の頭は和音の音に寄せる。左右に振り分け、リバーブ（コム4本＋オールパス2本）。
  - 型の選び方：材料ごとに「選ばれやすさ」を足して、くじを引く（雨・つらい・暑い→ローファイ、トレイル・ふつう→ジャジー、
    ロード・楽しい・晴れ→ハウス、ロード・がんばった・寒い→クラブ）。響き（明るい／しっとり／ドリアの2コード）は気分＋天気。

## 残りの機能（本人の選択で追加。2026-11-14）

- **未舗装の道の判定（仕様 9章の3つ目の目安）**
  - 走り終わったあと（`RunService` から別の処理で）と、記録の画面を開いたとき（まだ調べていなければ）に、`PostRun.checkSurface` で調べる。
  - ルートの形（50m ごとの点、最大 300 点に間引く。**隠す場所のまわりの点は送らない**）を、Overpass API（overpass-api.de、無料・鍵なし）に送り、
    まわり 25m の道（highway の付いた way）を、種類と形ごと受け取る（`run/OsmApi.kt`）。
  - 点ごとに、いちばん近い道（25m 以内）が未舗装かを決める（`core/Surface.kt`）：路面（surface）が土・砂利・草などなら未舗装、
    アスファルトなどなら舗装。路面の情報がなければ、path・bridleway・track（grade1 以外）と、sac_scale などが付いた道は未舗装。階段は数えない。
    近くに道が見つかった点が半分未満なら「分からない」。
  - 結果は runs 表の `unpavedFraction`（null＝まだ、-1＝分からない、0〜1）。**データベースの版を 7 → 8 に上げた**。
  - 判定は「3つのうち2つ」に変えた（`RouteAnalysis.looksLikeTrail`）。高さが分からないときは未舗装だけ、道の種類が分からないときは登りと坂の両方（前と同じ）。
    未舗装の目安は初期 30%（設定で 5〜95%）。設定で、調べること自体をオフにできる。
  - 判定のやり直しは、走ってから6時間以内だけ（昔の記録で急に聞かないように）。コースの種類が決まっていれば、そちらを優先。
  - 記録の画面に「未舗装の道 ○○%」「急な坂 ○○%」と、出典（© OpenStreetMap contributors）を出す。
  - **実機で未確認。** 生田緑地で、地図の情報が十分か（道が描かれているか、surface が付いているか）は走ってみないと分からない。
- **プレイリスト（仕様 1-6）**
  - m3u・m3u8 を選ぶと（ストレージ アクセス フレームワーク）、中の曲を、曲のフォルダの曲に結びつけ、その曲だけ「使う」にする（ほかはオフ）。
    「全部の曲に戻す」で全部オンに戻す。曲の順番は使わない（テンポで選ぶため）。
  - 結びつけ方（`core/Playlist.kt`）：ファイル名が同じ曲のうち、うしろからフォルダ名が多く一致する曲。大文字・小文字は区別しない。
    file://、%xx、\ 区切り、BOM に対応。文字化けしたら Shift_JIS で読み直す。
  - 読み込んだプレイリストの名前だけを設定に残す（`playlistName`）。データベースは変えていない。
- **地図の画像書き出し（仕様 2-5）**
  - 記録の画面の「地図を画像で書き出す（共有）」。ランムービーの地図の場面と同じ描き方（隠す場所のまわりは描かない）に、
    日付・場所・タイム・平均ペース・登りを足した 720×1280 の PNG。アプリのキャッシュに置いて、共有メニューで外に出す。
