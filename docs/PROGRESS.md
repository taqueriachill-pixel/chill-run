## 作り始める前に伝えたこと（仕様で気をつける点）

- リポジトリが「公開」になっている（仕様書と APK が誰でも見られる）。非公開にするかは本人が決める。
- **心拍数**：PowerBuds は Zepp でワークアウトを始めたときだけ測る可能性が高い。
  ヘルスコネクト経由だと Zepp でも同時に記録が必要になり、ランが二重になるおそれ。
  PowerBuds Pro には、心拍数をほかのアプリへリアルタイムに渡す機能がある（説明書）。
  本人の機種が Pro かどうか、標準の形式（0x180D）で流れるかは nRF Connect で確認する。
  だめなら標準規格の心拍ベルトを提案する。
- **ロック画面**：「走っている画面」を開いたまま画面を消した場合は、電源ボタンで解除なしに出る。
  ホームに戻ってから消した場合は、通知をタップして開く（Android の決まり）。
- **声の文字化**：端末内の音声認識が録音ファイル・日本語で使えるかは段階3で実機確認。だめなら whisper.cpp など。
- アプリ内の音楽（段階5）は、読み上げ中の音量下げをアプリ自身で行う必要がある。
- ヘルスコネクトに「筋肉量」はない。除脂肪体重・骨量・体水分量・基礎代謝を読む。
- ヘルスコネクトは標準では過去30日までしか読めないので、「過去のデータを読む」許可も求めている。
- GPS の高さは日本では約37m 高く出るので補正する。
- ランムービーの地図にも「出典：国土地理院」を入れる。地図の一時保存は狭い範囲だけ。
- 未舗装かどうかの判定（OpenStreetMap）は通信があるときだけの、おまけの判定材料にする。

## 本人が決めたこと（2026-11-12）

- **同じランがほかのアプリ（Google Fit、Zepp など）と二重に記録されても構わない。** ほかのアプリの記録は見返さないため。
  - 二重を防ぐための作り込みや設定の案内はしない（仕様3章の「同じランが2回記録されないようにする」は、ここまでで十分とする）。
  - Chill Run 自身が同じランを2回書かないこと（ランごとの決まった番号）だけは続ける。
  - 心拍数は「Zepp でも同時にワークアウトを記録して、あとでヘルスコネクトから取り込む」方法も選択肢に入る。

## 実機で分かったこと（2026-11-12）

- 気圧センサー（lps22hh）、歩数センサー（1歩ごと・合計）あり。日本語の読み上げは通信なしで使える声が5個。
- ヘルスコネクトの許可は 16/16。心拍数・体重などは「データなし」（Zepp と AIfit をまだヘルスコネクトにつないでいない）。
  運動の記録は Google Fit が自動で書いたウォーキング（種類番号79）が128件。
- Zepp の PowerBuds の「運動設定」に **「アクティビティ心拍数の共有」**（付近のスマートデバイスが心拍数データを取得できる）があり、オンになっている。
  → 心拍数を Bluetooth で直接流している見込みが高い。標準の形式（0x180D）かどうかを nRF Connect で確かめる（`docs/SETUP.md` の 8）。
  流れるのがワークアウト中だけかどうかも、あわせて確かめる。

## 段階1で決めたこと

### 全体
- アプリの ID：`com.chill.run`。対応は Android 14 以上（minSdk 34）、Android 16 向け（targetSdk 36）。
- Kotlin + Jetpack Compose。画面の切り替えは自前の簡単な仕組み（`MainActivity` の `route`）。
- ビルド：GitHub Actions（`.github/workflows/build.yml`）。どのブランチに push しても動く。
  - 鍵が登録済み → 固定の鍵で署名した APK を作り、Releases に `v0.1.<実行番号>` として置く。
  - 鍵が未登録 → 仮の鍵でビルドが通るかだけ確かめる（配らない）。
- 署名の鍵：Claude が作成し、本人にチャットで渡した。別名（alias）は `chillrun`。リポジトリには入れない。
- Claude の作業場所では Android のビルドができない。計算部分（`core`）だけは手元でテストできる
  （Gradle に入っている Kotlin コンパイラを使用）。それ以外は GitHub Actions の結果で確認する。
- Claude からは GitHub の Secrets を読み書きできない。

### 記録
- 位置は Android 標準の GPS（`LocationManager` の GPS_PROVIDER、1秒ごと）。Google Play 開発者サービスには頼らない。
- 精度 30m より悪い位置は使わない。2.5m 未満の動きは足さない（止まっているときのゆれ対策）。秒速12m を超える飛びは捨てる。
- 常駐サービスは type `location` のみ（`microphone` と `camera` は段階3で足す）。走っている間は CPU を起こしたままにする（wake lock）。
- 自動の一時停止：歩数が4秒なく、速さが秒速0.8m 未満なら止める。3秒で3歩以上、または秒速1.5m 超で再開。
  歩数センサーが使えないときは速さだけで判定。急坂をゆっくり歩いても止まらない。
- ケイデンス：歩数センサー（1歩ごと）の直近20秒から計算。
- 途中でアプリが落ちた場合：次に開いたときに、保存済みの地点から記録を仕上げる。
- 20m 未満で終了した記録は保存しない。

### 標高
- 気圧センサーを優先。気圧から出した高さ（相対値）を地点に保存し、ランごとの「ずれ」（`altOffset`）を足して標高にする。
- 開始地点の標高：最初の良い位置（精度20m 以内）で、まず GPS の高さで仮に合わせ、国土地理院の標高 API が取れたら置き換える。
- 獲得標高：なめらかにしてから、2.5m 以上の向きの変化だけ数える（気圧がない端末は 6m）。
- 記録に「標高：気圧／GPS」と「開始地点の合わせ方：地理院／GPS」を残す。

### 声のお知らせ
- 間隔：500m・1km・2km・5分・10分から選ぶ（初期は 1km）。伝える項目（ペース・前との比較・励まし）もオン・オフできる。
- 励ましの言葉：12 の場面 × 10 個を `assets/phrases.json` に用意。設定から書き出し・読み込み・初期に戻すができる。
  段階1で使う場面は 走り始め／ペースが上がった・落ちた・安定／後半に入った／最後の区間／目標達成。
  登り・下り・心拍・自己ベストの言葉は用意だけしてあり、段階2・4・6で使う。
- 目標の手前：距離は あと1km・500m・100m、時間は あと5分・1分・10秒から1秒ごと。達成で効果音＋振動＋「目標達成！」。
- 通信なしで使える日本語の声があれば、それを優先して使う。

### 画面
- ホーム（種類・メニュー・スタート）、走っている画面（ロック中も表示、長押しで一時停止・終了）、
  記録の一覧、記録の画面（数字・1km ごとの表・ルートの形・標高の線）、設定、許可の状態、実機チェック。
- 色：ロード＝海の青 `#2E9BD6`、トレイル＝森の緑 `#3DAA6B`。走っている画面は黒地に白の大きな数字。
- 細かいデザインは、段階1の実機確認のあとで相談する（仕様10章）。

### ヘルスコネクト
- 書き込み：運動（RUNNING。トレイルは題に「トレイル」）、ルート、距離、獲得標高、ケイデンス、消費カロリー。
  ランごとに決まった番号を付けるので、書き直しても二重にならない。
- 読み込み（段階1では実機チェックと体重の取り込みだけ）：心拍数、安静時心拍数、体重、体脂肪率、除脂肪体重、骨量、体水分量、基礎代謝、運動の記録。
- 消費カロリーの目安：体重 × 距離(km) × 1.036 ＋ 登りの分。
